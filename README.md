# MacroKit

Макро-программа для клавиатуры под Windows. Замена макро-части родного софта производителя.

Работает на .NET Framework 4.8, встроенном в Windows.

## Установка и обновление

Установщик — в [релизах](https://github.com/awakkarts-ux/macrokit/releases):
`MacroKit-Setup-X.Y.Z.exe`. Ставится в профиль пользователя
(`%LOCALAPPDATA%\Programs\MacroKit`), прав администратора не просит.
Настройки живут отдельно, в `%APPDATA%\MacroKit`, — установка, обновление и
удаление их не трогают.

Обновление — шестерёнка внизу левой полосы → «Обновить до …». При запуске
программа сама смотрит последний релиз и, если есть новее, ставит точку на
шестерёнке. По кнопке она скачивает установщик (сверяет размер и SHA-256),
запускает его в тихом режиме и закрывается; установщик заменяет файлы и
запускает новую версию.

Список изменений — [CHANGELOG.md](CHANGELOG.md).

## Зачем

Родной софт клавиатуры проигрывает макрос **прямо внутри колбэка низкоуровневого хука**,
со `Sleep()` между нажатиями. Последствия:

- колбэк хука вызывается системой последовательно, в одном потоке — пока он спит,
  вся клавиатура в системе стоит в очереди. Отсюда «нажал один макрос, остальные кнопки не работают»;
- у Windows есть таймаут `LowLevelHooksTimeout` (по умолчанию 300 мс). Не уложился — система
  молча выкидывает хук из обработки. Отсюда случайные пропуски и залипания;
- `Sleep(5)` без `timeBeginPeriod(1)` реально спит около 15 мс, поэтому заданные в интерфейсе
  задержки не соблюдаются.

Здесь всё это разведено:

| | родной софт | MacroKit |
|---|---|---|
| Где играет макрос | в колбэке хука | в отдельном потоке на каждый макрос |
| Что делает колбэк | всё | поиск в массиве и взвод события, без аллокаций |
| Задержки | `Sleep`, шаг ~15 мс | waitable-таймер высокого разрешения + спин на хвосте |
| Два макроса сразу | второй ждёт первого | играют параллельно |
| Обрыв на середине | клавиша залипает | все зажатые клавиши отпускаются |

Замеры на реальном прогоне (`bin\SmokeTest.exe`): последовательность из 6 событий на 290 мс —
максимальное отклонение **1.0 мс**. Два макроса по 4 шага: **266 мс** вместо ~520 мс,
если бы они стояли в очереди.

## Сборка

```
powershell -ExecutionPolicy Bypass -File build.ps1
```

Результат — `bin\MacroKit.exe`, без зависимостей, и рядом
`bin\SmokeTest.exe` с автопроверкой движка.

Версия берётся из файла `VERSION` (можно переопределить: `build.ps1 -Version 1.2.3`):
скрипт пишет её в `obj\AssemblyInfo.g.cs`, и она попадает в свойства exe. Программа
сравнивает её с последним релизом, когда проверяет обновления.

### Выпуск версии

1. Поднять `VERSION`, дописать раздел `## X.Y.Z` в `CHANGELOG.md`, закоммитить в `main`.
2. `git tag vX.Y.Z && git push origin vX.Y.Z`.
3. GitHub Actions (`.github/workflows/release.yml`) собирает программу на Windows,
   собирает установщик Inno Setup (`installer\MacroKit.iss`) и создаёт релиз с
   `MacroKit-Setup-X.Y.Z.exe` и текстом из `CHANGELOG.md`. Тег и `VERSION` обязаны
   совпадать — иначе сборка остановится.

Эталонная копия workflow лежит в `installer\release.yml`: workflow-файлы в
`.github` добавляются через веб-интерфейс GitHub.

Тест собирается тем же скриптом намеренно: пока он был отдельной ручной командой,
он однажды на две недели отстал от кода и показывал зелёное, проверяя движок,
которого уже нет. Если тест не собрался, скрипт падает с ненулевым кодом, даже когда
сама программа собралась — молчаливый пропуск здесь хуже громкой ошибки.

Оформление — тёмный графит, общий с «Сборщиком интерфейса Aion» (токены и принцип
«крупные мягкие контролы» те же, `src\Ui\Theme.cs`). Шрифты Onest и JetBrains Mono лежат
в `fonts\ui` статическими начертаниями (OFL) и вкладываются в exe ресурсами; программа
регистрирует их сама (`src\Ui\Fonts.cs`), ставить в систему не нужно. Variable-файл
не подходит: GDI, которым рисует WinForms, оси не понимает.

Скрипт сам находит компилятор: сначала Roslyn от VS Build Tools, если его нет —
встроенный `csc.exe` из .NET Framework.

Иконку скрипт при необходимости генерирует сам (`tools\make-icon.ps1`) и встраивает
дважды: как Win32-ресурс — для Проводника и ярлыка, и как ресурс сборки — для окна
и панели задач. Это разные механизмы, одного не хватает.

## Проверка движка

```
bin\SmokeTest.exe
```

Тест ставит собственный хук, который ловит и **глушит** инъекции самого MacroKit.
Поэтому он видит ровно то, что макрос отправляет в систему, но ни одна клавиша
не долетает ни до одного приложения — запускать безопасно.

Проверяется: порядок событий, точность задержек, параллельность макросов,
отсутствие залипших клавиш при обрыве, режим счётчика повторов, разбор `.mac`,
раскрытие слайда и определение конфликтов триггеров.

Отдельно собирать не нужно: `build.ps1` делает это сам, из тех же исходников, что и
программу, минус `Program.cs` — у теста своя точка входа.

Не на Windows (Mono на Linux) тест ставит не хук, а подмену отправки
(`InputSender.Sink`), а состояние клавиш — заглушку (`KeyState.AsyncDown`). Так логика
слайдов, конфига и пересборки проверяется и без Windows; тайминги там грубее.

Случай «W зажата пальцем» тест проверяет: палец имитируется через
`KeyState.OnPhysical` — ровно так его видит движок из хука.

Чего тест проверить не может: случай «модификатор зажат физически» — он завязан
на `GetAsyncKeyState`, а хук теста глушит все инъекции, поэтому подделать зажатую
клавишу нечем. Такое проверяется только вживую.

## Как устроено

```
src/
  Native.cs         объявления WinAPI
  KeyboardHook.cs   глобальный хук на своём потоке с циклом сообщений
  InputSender.cs    отправка ввода scan-кодами + подпись своих событий, учёт зажатого
  KeyState.cs       что пользователь держит пальцем и какие клавиши «у слайда»
  Precision.cs      точная прерываемая пауза
  MacroEngine.cs    привязки, проигрыватели, запись, сторож хука
  Model.cs          модель данных
  ConfigStore.cs    чтение и запись JSON, копии, одноразовые переделки
  ChatLog.cs        чтение Chat.log игры
  Journal.cs        журналы задержек и лент слайдов
  ForegroundApp.cs  процесс активного окна — для «только в игре»
  Updater.cs        проверка релизов GitHub и запуск установщика
  Ui/               интерфейс
tests/
  Smoke.cs          автопроверка движка
installer/
  MacroKit.iss      установщик Inno Setup
  release.yml       эталон workflow выпуска
```

Два принципиальных решения в отправке ввода:

1. **Scan-коды, а не виртуальные клавиши.** Приложения, читающие ввод через DirectInput
   или Raw Input, виртуальные коды часто не видят вовсе. Это причина номер один,
   по которой самописные макросы «не срабатывают».
2. **Подпись в `dwExtraInfo`.** Хук пропускает свои же события мимо, иначе макрос,
   нажимающий собственную клавишу-триггер, ушёл бы в бесконечную рекурсию.

## Профили

Независимые наборы макросов: один под лучника, другой под другой класс, третий пустой
вместо выключателя. Значки в левой полосе — как серверы в Discord.

- **левый клик** — переключиться
- **правый клик** — переименовать, дублировать, удалить
- **наведение** — полное имя и число макросов
- **«+» внизу** — новый профиль

Профили не пересекаются: правка в одном не может задеть другой. Платим за это тем,
что общие макросы приходится копировать — для этого есть «дублировать».

**Переключаться можно посреди работающего макроса.** `MacroEngine.Apply()` пересобирает
карту привязок целиком, подменяет её атомарно и диспозит старые проигрыватели, а те в
`Dispose()` отпускают всё зажатое. Зажатый `W` из слайда не залипнет.

Старые конфиги с макросами в корне читаются и заворачиваются в профиль «Основной» —
при обновлении ничего не теряется и делать ничего не надо.

## Триггеры и модификаторы

Триггер — клавиша плюс любая комбинация из `Ctrl`, `Alt`, `Shift` и **двух боковых
кнопок мыши**.

Боковые кнопки читаются тем же `GetAsyncKeyState` прямо в колбэке хука
(`VK_XBUTTON1 = 0x05`, `VK_XBUTTON2 = 0x06`) — мышиный хук не нужен.

Чем они лучше клавиатурных модификаторов: боковая кнопка **не является клавишей
клавиатуры**, поэтому физически не может подмешаться в инъектируемые макросом
нажатия. С зажатым `Shift` такое бывает — в игру уходит `Shift+W` вместо `W`.

Сравнение модификаторов **точное**, а не «содержит». Благодаря этому на одной клавише
спокойно живут два макроса — спам без модификаторов и слайд с боковой кнопкой — и они
никогда не срабатывают вместе.

**Кнопка всё равно доходит до игры:** клавиатурный хук мышь не глушит. Если боковая
кнопка на что-то забиндена — снимите бинд в игре.

### Конфликт триггеров

Если два **включённых** макроса сидят на одной клавише с одинаковыми модификаторами,
движок запустит оба разом. Такие макросы помечаются в списке красной точкой и красной
подписью «занята другим макросом», при наведении — что с этим делать.

Выключенные макросы и макросы без триггера конфликт не создают.

## Режимы повтора

- **Один раз за нажатие** — отыграл и остановился.
- **Пока держу клавишу** — крутится по кругу, пока клавиша зажата.
- **Тумблер** — нажал: пошло; нажал ещё раз: встало.
- **Заданное число повторов** — ровно N проходов.

Для первого и последнего режимов настраивается поведение при повторном нажатии
во время проигрыша: начать заново, не прерывать, остановить.

Разные макросы всегда играют независимо друг от друга.

## Действие «Слайд»

Отмена анимации бегом с прыжком. Раскрывается в семь примитивов на лету, а не хранится
семью шагами: скелет у всех слайдов одинаковый, а править тайминги хочется в одном месте.

```
скилл ↓↑  →  пауза на каст  →  бег ↓  →  прыжок ↓↑  →  добег  →  бег ↑
```

Параметры: клавиша скилла и её удержание, **модификатор скилла в игре**, пауза на каст,
клавиша движения и сколько её держать, прыжок и через сколько, разбег до скилла.

**Модификатор скилла — то, ради чего действие и делалось.** Скилл висит на `Alt+1`, а
слайд его оттуда и жмёт: зажать `Alt`, нажать клавишу, отпустить `Alt`. Дубль скилла на
свободный слот панели не нужен.

Проверено смоук-тестом: лента событий и тайминги совпадают с рукописным вариантом
из семи шагов посимвольно — `4↓ 4↑ W↓ Пробел↓ Пробел↑ W↑`, 0 / 0 / 20 / 40 / 60 / 440 мс.

### Что выяснилось на живых боях в Aion

- **Удержание клавиши скилла — 0 мс.** Нажатие и отпускание подряд. Значение 15 мс,
  которое напрашивается из соображений «а вдруг игра опрашивает клавиши по кадрам»,
  на практике даёт заметно больше промахов.
- **Разбег до скилла не помогает, а мешает.** Идея была в том, что прыжок с места
  анимацию не отменяет и персонажу нужен разгон. На деле бег до применения срывает
  сам скилл: персонаж просто бежит. Держите разбег в нуле, пока не найдёте случай,
  где он нужен.
- Рабочая конфигурация, дающая примерно 19 срабатываний из 20: удержание 0, разбег 0,
  каст 20 мс, бег 420 мс, прыжок через 20 мс.

### Слайд в прыжке

Второй вид слайда (jumpshot): сначала прыжок, скилл жмётся в воздухе.

```
[W↓ разбег]  Пробел ↓↑  [W↑]  →  пик  →  автоатака  →  скилл  →  приземление  →  [бег]
```

Движение в воздухе срывает выстрел, поэтому W отпускается сразу после прыжка и
возвращается только после приземления. Автоатака (по умолчанию `C`) добавляет свой
удар к удару скилла. Стартовые тайминги — пик 300 мс, автоатака→скилл 20 мс,
приземление 350 мс — **не проверены в игре**, их надо подбирать.

## Один макрос на ряд клавиш

Кнопка «Клавиши…» рядом с триггером. Макрос получает список клавиш, а в действиях
вместо конкретной клавиши ставится **«клавиша триггера»** (галочка «Скилл = клавиша
триггера» в слайде). Движок раскрывает такой макрос в копию на каждую клавишу:
один «Спам» обслуживает четырнадцать скиллов, один «Слайд» — весь ряд.

Слайды играют строго по одному: новый слайд останавливает идущий, иначе они
дрались бы за W и пробел.

### Клавиша-слой

Там же, в «Клавиши…». Держится как модификатор, но **в игру не уходит никогда**:
движок глотает её и сам помнит, зажата ли она. Макросы без слоя молчат, пока слой
зажат, — сравнение точное, как у Ctrl / Alt / Shift.

### Alt-скиллы под слоем

Ctrl / Alt / Shift, нажатые **после** слоя, тоже глотаются: под макросы они
подходят, а игра их не видит. Поэтому слайд Alt-скилла жмёт Alt сам, только на
время нажатия скилла, и бег с прыжком уходят в игру чистыми, а не `Alt+W`.
Слоем считается и боковая кнопка мыши, если на ней висит хотя бы один слайд.

Порядок важен: **сначала слой, потом Alt.** Alt, нажатый раньше, уже ушёл в систему,
а отпускать чужую зажатую клавишу нельзя (см. «Что стоит знать»).

### W, зажатая рукой

Галочка «Учитывать W, зажатую рукой» в окне слайда. Лучник кайтит с зажатой W, а
у слайда без неё две беды:

- **в прыжке** игра должна «увидеть остановку» в воздухе — иначе выстрел срывается.
  Чужую W слайд отпустить не мог, и джампшот на бегу не срабатывал;
- **с места** слайд в конце отпускал W — персонаж вставал, хотя палец на клавише.

С галочкой слайд на время проигрыша забирает W себе (`KeyState.Own`): события W с
клавиатуры, включая автоповтор, до игры не доходят, а палец движок запоминает по
хуку. Слайд в прыжке отпускает W после прыжка; слайд с места сначала
останавливает бегущего персонажа — он подобран под стоящего. В конце, в том числе
при обрыве, W возвращается в то состояние, в котором её держит палец.

Почему своё состояние, а не `GetAsyncKeyState`: после того как слайд отпустил W,
система честно считает её отпущенной — узнать, держит ли её палец, больше неоткуда.

Новые слайды создаются с галочкой. У слайдов из старых конфигов поля нет, и оно
читается как «выключено» — поведение прежнее. Для каждого профиля со слайдами
программа один раз создаёт копию «… · W рукой» с включённой галочкой.

Рядом — **клавиша прыжка**, если в игре прыжок не на пробеле.

## Настройки

Шестерёнка внизу левой полосы.

- **Только когда активно окно игры.** Процесс по умолчанию — `aion.bin`, есть выбор
  из запущенных. В другом окне клавиши работают как обычно, а при уходе из игры
  всё играющее останавливается. Имя процесса читается и у игры, запущенной от
  администратора. Окно самой MacroKit — тоже «не игра»: кнопка «Тест» работает,
  а клавиши, пока настраиваешь, — нет.
- **Пауза на чат.** Enter ставит макросы на паузу, Enter или Esc снимает. Программа
  не видит, открыт ли чат в игре, поэтому это эвристика: если открыть чат мышью,
  она не узнает.
- **Клавиша вкл / выкл движка**, по умолчанию Pause. До игры не доходит, работает и
  при выключенном движке.
- **FPS игры** — тогда длительность слайда показывается ещё и в кадрах. Игра
  опрашивает клавиатуру раз в кадр: 20 мс при 60 FPS — это один кадр.
- **Журнал слайдов** — фактическая лента событий каждого слайда в
  `slides-timing.txt` рядом с конфигом: что ушло и через сколько миллисекунд.
- **Версия и обновление.**

Внизу списка макросов — состояние: «Ждёт окно игры», «Пауза: чат», «Движок
выключен · Pause».

### Сторож хука

Windows молча снимает низкоуровневый хук, если колбэк хоть раз не уложился в
таймаут (подвисание системы, загрузка игры), — и макросы перестают работать до
перезапуска. Раз в две секунды программа проверяет: если система видела ввод, а
хук давно молчит, она отправляет «зонд» — отпускание неназначенной клавиши 0xE8 со
своей подписью. Хук не увидел его за секунду — хук ставится заново. Сколько раз
это было, видно в подсказке у строки состояния.

## Импорт .mac из родного софта

Кнопка со стрелкой вниз в шапке списка макросов. Можно выбрать сразу несколько файлов.

Про формат пришлось разобраться, документации на него нет:

- **`Button` — это HID Usage ID (страница 0x07), а не виртуальный код Windows.**
  26 там означает `W`, а не «стрелку вниз». Проверено на 13 файлах: расшифровка кода
  всегда совпадает с именем макроса (`slide_kite_Q` → 20 → `Q`, `slide_kite_B` → 5 → `B`).

- **`Delay` — пауза ПОСЛЕ события, а не перед ним.** Это видно по файлу
  `slide_kite_C_cast`: при обратном чтении пробел получал бы нулевое удержание в самом
  конце, что бессмысленно, а при правильном получается связная картина — тап скилла,
  пауза 270 мс на время каста (движение прервало бы его), затем движение.
  Косвенно подтверждает и то, что у последнего события `Delay` всегда 0 —
  ровно как и положено «паузе после».

При импорте пара «зажать X → отпустить X» схлопывается в одно нажатие с нужным
удержанием, чтобы список читался. Триггером подставляется первая клавиша макроса
(она же обычно в имени файла), но макрос остаётся **выключенным** — пока не включишь
галочкой, поведение клавиши не меняется.

Тайминги переносятся один в один.

## Конфиг

`%APPDATA%\MacroKit\config.json` — обычный JSON с отступами, правится руками.
Пишется через временный файл и подменяется одной операцией, так что обрыв на
середине записи его не портит.

- Перед перезаписью конфиг копируется в `backups\config-<дата>.json` — при первой
  записи после запуска и дальше не чаще раза в полчаса, хранятся последние 10.
- Если конфиг не читается (например, опечатка при ручной правке), он сохраняется
  как `config.broken-<дата>.json`, программа говорит об этом и стартует с чистыми
  настройками. Раньше первое же сохранение молча затирало файл.

```json
{
  "engineEnabled": true,
  "activeProfile": "<id>",
  "profiles": [
    { "id": "<id>", "name": "Основной", "macros": [ ... ] }
  ]
}
```

В корне, кроме профилей: `onlyInGame`, `gameProcess`, `chatPause`, `toggleVk`,
`gameFps`, `slideJournal`, `chatLogPath` и `migrations` — список выполненных
одноразовых переделок конфига.

У макроса, помимо триггера и модификаторов, есть `mouse4` и `mouse5` — боковые кнопки.
У действия вида `Slide` — свои поля: `skillCtrl`, `skillAlt`, `skillShift`, `castMs`,
`moveVk`, `runMs`, `preRunMs`, `jump`, `jumpAfterMs`, `freeMods`, `respectHeldMove`,
`jumpVk` (только если не пробел).

## Что стоит знать

- **Нельзя отпускать модификатор, который пользователь держит физически.** Инъекция
  отпускания переписывает состояние клавиатуры в системе: `Alt` становится
  «отпущенным» при физически зажатой клавише. Дальше рушится всё — сочетания с этим
  модификатором перестают подходить под макросы, клавиша не блокируется и проваливается
  в игру голой. Поэтому слайд зажимает только тот модификатор, которого ещё нет, и
  отпускает только то, что зажал сам. По той же причине галочка «отпустить зажатые
  Ctrl / Alt / Shift» по умолчанию снята — включать только если `Shift+W` или `Alt+W`
  реально мешают движению в конкретной игре.
- **Окна, запущенные от администратора.** Если игра или приложение запущено с повышенными
  правами, а MacroKit — нет, хук не увидит нажатия в этом окне. Лечится запуском
  MacroKit от администратора.
- **Модификаторы проверяются в момент нажатия клавиши.** Зажать клавишу, а потом
  добавить боковую кнопку мыши — не переключит на другой макрос. Сначала модификатор,
  потом клавиша.
- **«Пока держу» останавливается по завершении текущего прохода**, а не мгновенно.
  Сделано намеренно: обрыв на середине последовательности хуже, чем лишние 100–200 мс.
- **Своя W и чужая.** Правило «не отпускать то, что держит пользователь» для W
  нарушается сознательно — но только у слайдов с галочкой «W рукой», и только
  потому, что программа сама ведёт состояние пальца и в конце возвращает W ему.
- **Масштаб экрана.** Разметка в фиксированных пикселях, манифеста DPI нет.
  На 100% (текущая конфигурация) всё точно; при масштабе выше Windows растянет окно
  битмапом — станет слегка мягче.
- **Служебные клавиши клавиатуры.** Если клавиша шлёт собственный HID-репорт вместо
  обычного скан-кода, низкоуровневый хук её не увидит. Проверить можно через
  `key-tester.ps1`: если нажатие не появляется в окне — это как раз такой случай.
- Действия мыши — только кнопки, без перемещения курсора.
- Переключения профиля горячей клавишей пока нет, только мышью в окне.

## Вспомогательные скрипты

- `key-tester.ps1` — показывает, что шлёт каждая клавиша: имя, virtual key, scan code.
- `inject-test.ps1` — отправляет заданную последовательность в активное окно и печатает,
  за сколько реально уложилась.

Скрипты пишите **только в ASCII**: `powershell.exe` читает `.ps1` без BOM в ANSI,
кириллица разваливается и ломает разбор строк.
