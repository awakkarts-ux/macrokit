## 14.11 (вторая сессия) — v1.1.0: серии умений (читать первой)

**Запрос.** Как серии в 5.x: кнопка жмёт следующее по кругу умение не в кд, кд у всех разные; у кнопки 3 своя цепочка (Внезапный выстрел 12 с → Взрывной выстрел 24 с). Серия пользователя: 3 Внезапный (12 с) → продолжение Взрывной (24 с) → Alt+E Точный выстрел (3 мин) → Alt+Q Стрела грифона (1 мин). Жмёт кнопку частыми нажатиями («пока держу»). После последнего — снова с первого доступного; всё в кд — ничего.

**Решения пользователя.** Кд — по Chat.log (стан/дистанция: нажатие есть, скилла нет — таймер по нажатию врал бы). Снимки экрана — нет.

**Формат лога** (прислал 14.11, cp1251): свои умения `ВРЕМЯ : [Критический удар! ]Название РАНГ: цель получает … / оглушается …`; автоатака — `Вы нанесли …`; отказ — `Цель находится слишком далеко.`. Чат: `[3.Поиск группы] [charname:…]: …`. По логу кд сходятся: Внезапный 10→23→39→53 с, Взрывной 11→41; продолжение шло через 1–2 с после выстрела.

**Сделано** (`SkillTimers.cs`, `MacroRunner.PlaySeriesStep`, `Ui/SeriesDialog.cs`, `ActionKind.Series`, `SeriesSkill`):
- Шаблон умения `^время : (Критический удар! )?Название( [IVXL]+)?:` без регистра — чат и другие умения не подходят. Учёт кд общий (`SkillTimers`, слушает каждую строку ChatLog) — ручные нажатия тоже в кд
- Проход: следующее по кругу готовое → нажать (`PressSkill`, модификатор как у слайда) → ждать строку умения или отказа до `WaitMs` (`ChatLog.Expect` заводится ДО нажатия). Прошло — позиция дальше; нет — то же умение на следующем проходе. Всё в кд — пауза 15 мс. Позиция `_seriesPos` между нажатиями НЕ сбрасывается (иначе при частых нажатиях — всегда первое доступное)
- Продолжение (`Chain`): готово, только если предыдущее прошло ≤ `ChainWindowMs` (5000) назад и после него продолжения ещё не было
- Миграция `series-profile`: копия активного профиля «… · серия» + макрос `ConfigStore.RangerSeries()` без триггера, «пока держу»
- Конфиг: `useLog`, `chainWindowMs`, `series: [{name, vk, alt/shift/ctrl, cdMs, waitMs, chain}]`
- SmokeTest `TestSeries` с «игрой»-симулятором (пишет строки настоящего формата): порядок с продолжением, 0 нажатий в кд, стан, «слишком далеко» (36 мс), ручной каст, всё в кд, без лога, миграция, конфиг туда-обратно. Все проверки пройдены (Mono, 3 прогона)

**Не проверено:** в игре; окно `SeriesDialog` визуально (на Linux нет X — вёрстка проверена расчётом, окно 920 шириной). Неизвестно: окно продолжения в игре (взято 5 с), время каста Точного выстрела (`WaitMs` 1000 — если каст дольше, строка придёт позже, умение всё равно уйдёт в кд по слушателю), отличает ли сервер чужие умения в логе (в присланном логе чужих боёв нет).

**1.1.1 (после первого теста в игре).** Жалоба: срабатывала только 3 (Внезапный, затем Взрывной от повторных нажатий), дальше серия не шла, и была задержка. Причина — у пользователя был неверный путь к Chat.log (сам исправил, «всё работает»), а серия при неудаче повторяла то же умение, каждый раз ожидая WaitMs 1000. Исправлено: при неудаче позиция всё равно идёт дальше (кд не засчитан), `SkillTimers.BaseName` отрезает ранг (арабский/римский), в окне — состояние файла лога (`SkillTimers.LogStatus`, красным, если файла нет), стрелки ↑↓, подписи.

**Скорость — главное для пользователя** (серия — бурст, «каждая мс важна»). Сейчас следующее умение жмётся только после строки предыдущего в логе. Нужен замер: «Журнал макросов» → `chatlog-timing.txt` («прошло через N мс»). Если лог запаздывает сильнее анимации — делать режим без ожидания: нажал → «в ожидании» до WaitMs (не жать снова), позиция сразу дальше, кд — по логу асинхронно; продолжение разрешать по нажатию родителя, а не по строке. Вопрос: ставит ли Classic умение в очередь, если нажать во время анимации предыдущего (иначе нажатия теряются).

**Идея на будущее — оверлей кд** (пользователь, после теста серии): компактная панель скиллов в игре, скиллы из серий убрать с панели; оверлей программы поверх игры там, где пользователь его поставит, полупрозрачно подсвечивает иконку умения, когда оно откатилось. Иконки пришлёт. Данные уже есть — `SkillTimers` (кд по логу). Вопрос к пользователю до работы: умение, убранное с панели, теряет клавишу в игре — серии нечего будет жать; видимо, нужна отдельная (скрытая) панель с биндами. Сначала HTML-макет оверлея. Окно поверх игры: прозрачное, click-through, topmost — проверить с полноэкранным режимом игры (нужен оконный/без рамки).

## Что НЕ сработало
1. Variable-шрифт Onest (как в сборщике) — GDI оси не понимает; брать статические начертания
2. Шрифт только через `PrivateFontCollection` — TextRenderer (GDI) его не видит и подставляет системный; нужен ещё `AddFontMemResourceEx`
3. Google Fonts CSS API с браузерным UA отдаёт woff, порезанные по алфавитам; с UA curl по умолчанию — цельные TTF на каждое начертание
4. TextBox с Onest и `AutoSize` срезает «_» (имя `slide_kite_4` выглядело как `slide kite 4`) — `Box.AutoSize = false`, высота `Font.Height + 6`
5. `SectionLabel` фиксированной ширины 220 в «Слайде» закрывали соседние подписи колонок — ширина по тексту
6. Снимок `PrintWindow` безрамочных окон (`PromptDialog`, `CaptureDialog`) — чёрный; для них `DrawToBitmap`. Диалог сразу после `Show()` снимается недорисованным (белые прямоугольники) — дать 10 × `DoEvents` + 40 мс
7. Пересборка при запущенной программе — `CS2012: Cannot open …MacroKit.exe for writing`
